Accessing WombatOAM
-------------------

WombatOAM runs in the pod "wombat" in the namespace "monitoring", behind the
service "wombat" (type LoadBalancer, port 8080). Without a load balancer,
forward a local port:

  kubectl -n monitoring port-forward pod/wombat 8080:8080

and open http://localhost:8080.

Log in as admin/admin and change the password straight away, under
Configuration > Change password, or from the command line:

  kubectl -n monitoring exec wombat -- python3 /wombat/wombat-headless.py change_password --password <new password>

Kubernetes discovery
--------------------
{{- $d := .Values.kubernetesDiscovery }}
{{- if and $d.service $d.namespace $d.appname $d.cookie }}

Pods behind the service "{{ $d.service }}" in the namespace "{{ $d.namespace }}"
are added automatically as nodes named {{ $d.appname }}@<pod IP>.
{{- else }}

Kubernetes discovery is off: set all of kubernetesDiscovery.service, namespace,
appname and cookie to add the pods of a service automatically. Nodes can always
be added from the WombatOAM GUI.
{{- end }}
{{- if .Values.wombatConfig.enabled }}

Settings saved from the GUI are kept in {{ .Values.hostPath }}/config/wombat.config
on the node.
{{- else }}

Settings saved from the GUI are lost when the pod is recreated. Set
wombatConfig.enabled=true to keep them in {{ .Values.hostPath }}/config.
{{- end }}

-----------------

If you have any questions or problems, please:

* First check the WombatOAM documentation.

* If you don't find an answer there, please send an email to
  wombat@erlang-solutions.com.

* If you are facing a technical issue, please execute
  scripts/wombat-debug.sh in the pod and send the generated tar ball to us.
